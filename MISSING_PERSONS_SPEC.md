## 1. Назначение и сценарий

**Що робить функція:**
Моніторинг окремих каналів про зниклих людей у пошуках згадок про конкретних осіб за списком ПІБ з Google Sheets.

**Відмінність від основного live/архіву:**
- Основний live: пошук по ключових словах (поліція, зброя, ДТП) в усіх каналах
- Основний архів: пошук по словах за період в усіх каналах
- **Пошук зниклих (НОВИЙ):** пошук конкретних ЛЮДЕЙ по ПІБ в окремих спеціалізованих каналах, повністю незалежна система

**Режимів роботи:**
- **Live режим:** автоматичний, 2 рази на день (08:00 та 20:00)
- **Архівний пошук:** ручний, по запиту користувача, введення ПІБ

## 3. Live режим (Автоматичний - 2x на день)

### Час виконання
**08:00 та 20:00 UTC+3 (Київський час)**

### Логіка роботи

1. **Завантажити дані з Google Sheets:**
   - Список каналів з листа "Channels Missing"
   - Список осіб зі статусом "missing" з листа "Missing Persons"
   - Кешувати на 1 годину щоб не перегруджувати API

2. **Обробити канали партіями:**
   - Партія = 5 каналів одночасно
   - Затримка 2 сек між каналами
   - Чекай 30 сек між партіями (охолодження)
   - Приклад: Каналів 20 → 4 партії по 30 сек = ~4 хвилини загального часу

3. **Для кожного каналу:**
   - Отримай останні 50 постів (за останні 24 години)
   - Перевір чи є ПІБ зі списку в текстах постів
   - Нормалізуй текст (нижні регістр, прибери пробіли)

4. **Якщо знайдено:**
   - **Одразу запис в Google Sheets** лист "Mentions"
   - **Одразу алерт адміну** в особистий чат бота
   - Перевір по URL щоб не дублювати

### Обмеження на запити

- **5 каналів паралельно** (не більше)
- **2 сек затримка між каналами** (людиноподібна поведінка)
- **30 сек пауза між партіями** (охолодження для Telegram)
- **Макс 50 постів на канал** (не скачуємо весь архив)

### При FloodWaitError

- Якщо < 30 сек → чекай, повтори партію
- Якщо > 30 сек → скипни цю партію, запиши помилку в логи, продовж наступну
- Не припиняй весь live, продовжуй інші партії

## 4. Архівний пошук (На запит - ручний)

### Логіка роботи

1. Адмін нажимає кнопку "🔍 Пошук за ПІБ"
2. Бот питає: "Введіть ПІБ для пошуку:"
3. Адмін вводить ПІБ (будь-яку форму)
4. Бот шукає по **ВСІХ каналах** в черговій системі
5. Результати: чат + Google Sheets "Mentions"

### Обробка множини каналів (20+)

**Queue-based підхід (для запобігання забороні):**

```
Адмін вводить: "Петренко"
         ↓
    Чергова створена
         ↓
    Черга 1 (обробляється):
    · agumova_chat → пошук (2 сек)
    · poloneniukr → пошук (2 сек)
    · UkrRFpl → пошук (2 сек)
    · info_poshuk → пошук (2 сек)
    · PoshukDopomoga → пошук (2 сек)
    ⏸ ПАУЗА 30 сек
         ↓
    Черга 2 (чекає):
    · mariya_ukraine → пошук (2 сек)
    · hpiloneni → пошук (2 сек)
    · ... тощо
         ↓
    ✅ Показати результати в чаті
    ✅ Записати в Sheets "Mentions"
```

### Параметри пошуку

**Період:** останні 500 постів або за 30 днів (що менше)

**Словоформи ПІБ (нормалізація):**
- Повне: "Петренко Петро Петрович"
- Скорочене: "Петренко Петро", "П. Петренко"
- Латиниця: "Petrenko" → автоматично як кирилиця
- З дефісом: "Петренко-Сидоренко"
- Варіацій без розділових знаків

**Стратегія пошуку:**
- Мінімум: Прізвище + перша буква імені ("Петренко П.")
- Опціонально: тільки Прізвище якщо немає ясного контексту

### При FloodWaitError під час архіву

- Якщо < 60 сек → чекай, повтори
- Якщо > 60 сек → **зупини пошук**, дай адміну те що вже знайшли, запропонуй повторити пізніше
- Не залишай адміна без відповіді

### Час виконання

Орієнтовно: **2-5 хвилин на 20 каналів** (залежить від розміру архіву та FloodWaitError)

## 7. Запитання які ти не поставив + Професійні Рішення

### 1️⃣ Як синхронізувати БД зниклих з основним live/архівом?

**Рішення:** Не синхронізувати. Два самостійні системи:
- **Система 1 (основна):** keywords → текущі новини про подій
- **Система 2 (нова):** ПІБ → розпорошені люди

Обробляти разом неефективно (різні каналі, різна частота, різні критерії). Простіша архітектура, менше помилок.

### 2️⃣ Що робити з дублями?

**Рішення:**
- Перевіряти по **URL** (унікальний за каналом + message_id)
- Якщо URL вже в Sheets → не дублювати
- Якщо один пост пошукаємо і в live, і в архіві → лише один запис в Sheets

### 3️⃣ Як знаходити варіації ПІБ?

**Стратегія нормалізації:**
```
Шукаємо: "Петренко Петро"

Знайдемо:
✅ "Петренко Петро Петрович"
✅ "П. Петренко"
✅ "Петренко П."
✅ "petrenco petro" (латиниця)
✅ "Петренко-Петро" (з дефісом)
❌ "Петренко" (тільки прізвище) — залежно від налаштувань

Алгоритм:
1. Нормалізуй текст: нижні регістр, прибери зайві пробіли
2. Замініть латиницю на кирилицю
3. Шукай повне ім'я або скорочене (Прізвище + першої 2-3 букви імені)
```

### 4️⃣ Як робити розписання live на 08:00 та 20:00?

**Рішення: APScheduler**

```python
from apscheduler.schedulers.asyncio import AsyncIOScheduler

scheduler = AsyncIOScheduler(timezone='Europe/Kyiv')
scheduler.add_job(
    search_missing_live,
    trigger='cron',
    hour='8,20',
    minute=0
)
scheduler.start()
```

Це вбудується в `bot.py` при запуску.

### 5️⃣ Як не спрацювати на бан при 20 каналах + 100 осіб?

**Парадокс:** Live 2x на день БЕЗПЕЧНІШЕ ніж часто:
- Live партіями по 5 каналів → Telegram бачить нормальну активність
- 2 сек затримка між каналами → людиноподібна
- 30 сек пауза між партіями → явна повага до rate limits
- 50 постів/канал → < 1 KB/sec трафіку
- Дедублікація → не спам-like повтори

**Протокол:** Якщо FloodWaitError > 30 сек під час live → просто скипни партію, логуй, продовжуй. Система робастна до затримок.

### 6️⃣ Як розрізняти пошуки (live vs manual)?

**Рішення: Колонка "Тип Пошуку" в Sheets**

```
Тип Пошуку: "auto" (live 08:00/20:00)
Тип Пошуку: "manual" (ручний архівний пошук)
```

Адміни потім фільтрують результати по типу.

### 7️⃣ Де брати останні пости без FloodWaitError?

**Рішення: limit + wait_time параметри**

```python
async for message in userbot.iter_messages(
    channel,
    limit=50,              # тільки 50 останніх (не весь архив)
    reverse=True,          # від нових до старих
    wait_time=0.5          # затримка вбудована в Telethon
):
    if message.date < since_date:
        break
    # обробка
```

### 8️⃣ Як робити timeout пошуку?

**Рішення: asyncio.wait_for**

```python
try:
    results = await asyncio.wait_for(
        search_in_all_channels(pib),
        timeout=600  # 10 хвилин максимум
    )
except asyncio.TimeoutError:
    await msg.answer(
        "⏱ Таймаут пошуку. Спробуй пізніше або "
        "введи менш популярне ім'я."
    )
```

### 9️⃣ Як не перегруджувати Google Sheets?

**Рішення:**
- Читати листи макс 1 раз на 5 хвилин (кешування в пам'яті)
- Писати "Mentions" батчем (10-20 рядків одночасно)
- `gspread` має вбудований retry механізм

### 🔟 Хто авторизується в Sheets?

**Рішення:**
- Один сервіс-акаунт (як зараз у бота)
- Таблиця шерується з адмінами на читання/запис
- БОТ має write доступ до "Mentions" листа
- Адміни можуть редагувати "Channels Missing" та "Missing Persons"

## 🔧 ТЕХНІЧНІ ЗАМІТКИ

### Важливі деталі реалізації

1. **Дедублікація**: перевіри по URL перед записом в Sheets
2. **Кешування**: завантажи списки осіб/каналів при старті, оновлюй кожні 5 хв

## 🐛 DEBUGGING

### Як тестувати

1. Додай 2-3 ПІБ в Google Sheets "Missing Persons"
2. Запусти `search_missing_live()` вручну (через Python консоль, не чекай 08:00)
3. Перевір чи записалось в "Mentions"
4. Спробуй архівний пошук з 1-2 ПІБ
5. Перевір FloodWaitError handling (спеціально введи FloodWaitError)

### Як логувати

```python
import logging

logger.info(
    f"Live search started: {len(persons)} persons in {len(channels)} channels"

)
```
